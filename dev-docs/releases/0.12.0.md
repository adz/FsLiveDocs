# FsLiveDocs 0.12.0

## Added

- `--timings` writes `.livedocs/timings.json` with phase and per-case durations and prints a summary.
- `run` and `transcript` fences may declare `deterministic` to reuse a passing result across invocations when the source, project, references, prelude, compiler, and tool are unchanged.
- Rendered code tokens link to their API reference pages; inline prose references link their qualified prefix (`` `FlowStream.runIntoQueue queue` `` links `FlowStream.runIntoQueue`).
- Transcript blocks render prompts in a non-selectable gutter, the result in a tinted band, and a Copy button. Transcript code gets hover and API links.

## Fixed

- Framework-pinned pages compile against that framework's own references, fixing "No overloads match" failures introduced in 0.11.1.
- The FSI load script opens the assembly's declared namespaces instead of a name derived from the project file.
- Updated the `GenerateLlmsTxtExample` snapshot for `PackageModel.Organization`.
- `release-local-tool.sh` falls back to `Directory.Build.props` `VersionPrefix` when the project file declares no `<Version>`.

## Improved

- `capture` is the single release verification pass; `test` and `capture` share one implementation, so the audit result feeds execution without re-walking, re-parsing, or re-compiling.
- Independent Markdown examples batch into per-project worker processes with a fresh FSI session each and bounded concurrency; snapshot examples keep their shared session.
- Release capture memory is bounded (Reified peaks around 1.4 GB instead of the prior 9.8 GB failure).

Release verification on Axial dropped from about 43 minutes to about 3.5 minutes.
