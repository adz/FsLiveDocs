# FsLiveDocs 0.14.5

## Fixed

- Resolve API extraction references through MSBuild's `ReferencePath` result, so framework references such as `Microsoft.AspNetCore.App` no longer leave FSharp.Formatting unable to resolve types like `Microsoft.AspNetCore.Http.HttpRequest`. The generated API model still contains only the documented project's own assemblies and namespaces.
- Compile pages without a `targetFramework` front-matter setting against their selected project's own references instead of the union of every selected project's target frameworks. Adding a net8-only project to a netstandard2.1 documentation set no longer changes what `System.Runtime` a guide resolves against.
- Key semantic page and whole-artifact caches on the selected documentation set and project, the requested and effective target framework, the configuration, and the exact ordered compiler references with their file contents (including adjacent XML documentation). A front-matter-only project change, a set project reorder, a reference rebuild, or a pinned framework's nondefault output now rechecks the pages it affects while unrelated pages keep their cached meaning. MSBuild evaluation still runs on a cache hit; only compiler checking is skipped. No persisted schema changes.
- Render an API sidebar entity once when a package section names both the entity and one of its nested children, rather than recursively rendering the child under its parent and again as a section entry.
- Keep both a parent and its explicitly listed child in the API sidebar, and let a companion type/module family keep nested children contributed only by the module. Family de-duplication now follows actual containment instead of matching dotted id prefixes, so similarly prefixed entities such as `Foo` and `FooBar` remain separate. An impossible cyclic family graph now fails with a clear error instead of silently removing the affected sidebar entries.
